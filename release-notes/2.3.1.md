## KoordASIO 2.3.1

A reliability release, and a simplification. Every change comes out of one
class of field report: "the driver won't load"
([#16](https://github.com/kormix-io/KoordASIO/issues/16)).

**[Download KoordASIO-Setup.exe](https://github.com/kormix-io/KoordASIO/releases/latest/download/KoordASIO-Setup.exe)** — 64-bit Windows, digitally signed.

### A missing or renumbered device no longer kills the driver

Previous versions always wrote the selected devices into the configuration by
name. Windows renumbers audio endpoints — unplug a USB interface, move it to
another port, dock a laptop, and "Speakers (3- USB Audio Device)" comes back
as "Speakers (4- USB Audio Device)" — after which the driver refused to load
at all, and the host reported a dead driver with no explanation.

The device selectors in KoordASIO Control now start on **"Windows default"**,
which names nothing in the configuration and simply follows whatever Windows
makes the default device — the same robust behavior FlexASIO has out of the
box, with nothing to go stale. Picking a specific device still pins it by
name, exactly as before; the difference is what happens when that device goes
away. KoordASIO Control re-matches a pinned device across Windows renumbering,
and when the device is truly gone it falls back to the Windows default instead
of leaving a dead driver behind.

Existing configurations keep working unchanged; a stale pinned name is
repaired the first time KoordASIO Control runs.

### Exclusive-mode sample-rate failures now explain themselves

If you choose Exclusive mode and your application runs at a sample rate the
device does not support natively — say a 44.1 kHz Ableton project on a
48 kHz-only interface — the stream cannot start, because Exclusive mode has no
sample-rate conversion. Previously the host reported a generic "driver failed"
and nothing more (stock FlexASIO fails the same way, silently). KoordASIO now
shows a dialog at the moment of failure: which rate was rejected, what rate
the device reports natively, and an offer to open KoordASIO Control so you can
switch to Shared mode on the spot. Hosts that display ASIO error text also get
the real reason instead of a generic malfunction code. This is KoordASIO's one
behavioral addition over the FlexASIO driver it is built on.

### The "mono → stereo" options are gone

They never worked: the underlying driver option they mapped to selects how
many *hardware* channels to open, so "present this mono microphone as stereo"
actually asked WASAPI for two channels from a one-channel device — which made
every sample rate probe fail and the host refuse to load the driver. The
checkboxes have been removed, and a leftover setting in an existing
configuration is cleaned up the first time KoordASIO Control runs. Hosts deal
with mono inputs fine on their own.

### Control panel polish

The panel now renders with Qt's software rasterizer, which removes occasional
triangular/line artifacts seen with some GPU drivers, and it no longer
re-queries the audio system on every settings change, which could make
control clicks feel sluggish.

### New defaults: Shared mode, 128-sample buffer

Fresh installs now start in WASAPI **Shared** mode with a **128-sample**
buffer, instead of Exclusive with 32. Exclusive mode has no sample-rate
conversion, so a host running at 44.1 kHz against a device that only does
48 kHz natively could not start — the other face of the same "driver won't
load" report. Shared mode accepts any sample rate and coexists with other
applications using the device. Exclusive mode — lowest latency, bit-perfect,
device locked to one application — remains one click away in KoordASIO
Control. Existing installs keep whatever mode and buffer they have configured.
